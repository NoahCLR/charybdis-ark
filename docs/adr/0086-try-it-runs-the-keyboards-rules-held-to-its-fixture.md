# Try it previews by the keyboard's rules, held to its fixture, and never edits its box

Cited as D-L86.

Ark has one matcher for the text replacement list (D-L84), `core/model/autocorrect-matcher.js`. It reads the characters a computer would show, with `\b` for Backspace, and answers with what the keyboard would leave on screen: which input fires when a word ends, the case its replacement takes, what the host layout can type under Caps Lock, the undo, and the limits of a word and of a replacement. The rules are the firmware's (`upstream/firmware/docs/spec/autocorrect-v1.md`, firmware D-F69), and every case of the firmware's behaviour fixture that has a text form (`screen`) is run through the matcher in `tests/model/autocorrect-matcher.test.js`. A case that needs a key, a timing or a setting (`keyboardOnly`) is listed as skipped with its reason, and a reason the test does not know fails it. A disagreement is settled in the firmware's spec and fixture first, never by changing the imported bytes.

A replacement that plays a macro is in the matcher too, since the fixture holds it: the input goes, there is no case rule and no undo, and a macro that is empty, or that the host's settings cannot play, is passed over. The matcher is told what each slot plays by its caller. Core gives it the macro's text when the macro types only text, so the preview shows what the computer would end with; for a macro of keys, shortcuts or waits it gives none, and the preview shows the input gone. Either way the answer names the slot that played, and the screen says so by the macro's name. Ark never plays a macro to find out.

Two things ask the matcher. **Try it**, the last section of a replacement's editor on the Text replacement screen (D-L88), shows what the keyboard would do with a sentence under the draft's list and host layout. The interface runs no rule: it reads its box as typing (text added at the end, one character gone as a Backspace, any other edit as text that stands, which is what a click is to the keyboard) and posts that to core (`tryAutocorrect`), which answers without staging anything. The list's warnings (D-L84) ask the same matcher which input fires on a replacement's own words, so a warning and the keyboard cannot disagree either.

## The box is the person's; the answer is a preview

Ark never changes what is typed into Try it. The box is a plain text field: whatever arrives in it stays as it arrived, and nothing Ark does writes to it but **Clear**. The matcher's answer is shown under it, in a read-only preview labelled "Preview with this draft: what your keyboard would type after you Apply." Each part a replacement typed is marked there and says on hover what it replaced; the matcher gives where each standing replacement's text is (`marks`, beside `fired`), and a part deleted since is no longer marked. The undo after Backspace and Caps Lock are the preview's alone: Backspace in the box is only a character gone, and **Preview with Caps Lock on** is a setting of the preview.

The first Try it wrote the matcher's answer back into its box, so the box read as if a keyboard had replaced in it. That was wrong wherever it ran. With a keyboard connected and text replacement on, the keyboard is already replacing what is typed into the box, by the list that is applied; Ark replacing as well, by the draft's, doubled the one or contradicted the other, and nothing on screen said which had done what. Without a keyboard it put words in the box the person had not typed. Two texts, the one typed and the one previewed, say what each is.

When the connected keyboard is replacing now, Try it says so beside its box: "Your keyboard is replacing as you type here too. The preview shows this draft." That is said only from what the keyboard reports (`autocorrectRunning`: its stored switch on, as read with its settings, and no switch key holding it off, as its runtime page says), never guessed, and never in the demo.

The switch that turns the feature on is not this screen's: it is a Host setting (D-L87).

## Considered

Running the matcher in the interface, as a shared rule (`rules/`, D-L73): the matcher needs the list, the word table and the host layouts' strokes, which core holds and the interface does not; a box typed in is quick enough over the panel boundary. A second, simpler matcher for the warnings: two homes for "which typo fires". Showing a made-up rendering of a macro's keys in the preview ("⌘Space"): the preview shows what the computer would end with, and a shortcut ends with nothing Ark can know. Writing the answer into the box, as first built: above. Turning the keyboard's own replacing off while the box is focused: Ark would be changing how the keyboard behaves to suit a preview, and the applied list is the one the person is living with.
