# Slots swap, and every reference follows

Cited as D-L81.

A macro, a custom key or a pointing mode is what it holds, not the slot it sits in. On the Macros, Custom keys and Pointing modes screens, a tile dragged onto another swaps the two slots (from the keyboard, Shift+Space holds a tile and Shift+Space on another drops it), so a person can put the things they use where they want them, as layers are put in order with Rename & reorder (D-L37). Each thing moves with everything that is its own: a macro's steps and name; a custom key's name, shortcut and behaviour row; a pointing mode's whole record, its link included, and on Lighting its colour and the accents that name it. Every reference follows, so nothing changes what it does: the keycodes on the keymap (`MACRO_n`, `CUSTOM_KEY_n`, `PD_MODE_n`, `PD_MODE_n_LOCK`), the actions in a behaviour's target and branches and in a combo's inputs and output, and the macro a pointing mode's direction taps run. Nothing else names a slot, so nothing else is rewritten: a macro's steps send only basic keys, a shortcut holds no userspace key, and no setting names a slot (`core/model/slot-order.js`, `tests/model/slot-order.test.js`).

The draft's order is now four banks, kept beside every history entry as the layer order was (D-L29): which keyboard layer, macro, custom key and pointing mode each slot holds, set only by what Rename & reorder or a swap did and never inferred (`core/model/draft-order.js`). Swaps compose: three swaps of a bank are one order. Review compares the draft with the keyboard's profile rearranged into that order, so a swap is one change per bank (**Macro order**, **Custom key order**, **Pointing mode order**, beside **Layer priority**) that says where each thing sits now, and everything else is compared thing with thing: a macro edited after a swap is its own change, Discard on the order puts every thing of that bank back where the keyboard holds it while the edits stay with their things, and the checks are matched slot with slot, so a swap makes or mends nothing by itself (`core/model/review-units.js`, `core/model/profile-review.js`, `core/session/profile-draft-session.js`). The screen's selection follows the thing that was dragged, and so does what was typed into its editor but not kept.

## Considered options

Moving a slot and shifting the others up, as a layer is moved: a bank is a fixed set of numbered slots that keys and the picker name by number, so an insert would renumber every slot between, and the person asked for places to be traded. Treating a swap as two ordinary edits, each slot changed whole: Review would then list both slots and every key, behaviour and combo that reached them as changed, and Discard on one would undo half a swap, which is why layers got an order of their own. Swapping only the two records and leaving the references: a key that typed a macro would type another, which is the one thing a swap must not do.
