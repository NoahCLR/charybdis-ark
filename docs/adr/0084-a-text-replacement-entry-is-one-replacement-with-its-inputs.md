# A text replacement entry is one replacement with its inputs

Cited as D-L84.

Ark edits the keyboard's autocorrect list (firmware D-F68) as **entries**, each one **replacement** with its **inputs**, what is typed to get it, the shape the firmware's domain stores. The list is for more than typos (a phone number for `pnumber`, a sign-off for `sig`), so a person reads replacement and input, never correction and typo, and the feature is text replacement (D-L87). The firmware's names are kept in the code: a replacement is a `correction` and an input a `typo` in the codec, the model, the contracts and the edits, as on the wire and in the imported fixtures.

The Text replacement screen lists a replacement once, with its inputs under it, and edits it with its inputs as chips (D-L88), never an item per input, and every edit names what it changes: a replacement by its text or its macro slot, an input by its stored letters. Adding a replacement the list already has adds to that entry, and changing a replacement to one the list has joins the two, so the list never holds one replacement twice; the screen offers to open the one it has instead of making it again, and says under the field that the two would join before a change is kept. An input belongs to one replacement, and one another replacement has is refused.

A replacement has one name wherever it is listed, and core gives it (`replacementCalled`, `core/model/autocorrect-list.js`): its text, or its macro's name ("Sign-off"), which every list draws after the macros' mark, the icon Macros and the key picker show (Review's `mark`, an entry's `macro`, an import summary's `macro`), never a character in the name; inside a sentence, its text in quotes or "the macro “Sign-off”" (`replacementSaid`). The panel publishes it as each entry's `label`, and the bank, the editor's title, Review, an import's summary and a refused line all read that one. The interface derives none.

## Where an input matches is written with `*`

The keyboard stores one of four matches with each input: the whole word, the start of a word, the end, or anywhere in one. Ark has no control, label or message for them. An input is the whole word unless it is written with `*` where other letters may go: `recieve*` the start, `*mnet` the end, `*tihng*` anywhere. Core reads the `*` (`inputOf`) and writes it back (`inputForm`); a chip shows the input as it is stored, folded to small letters, with its `*` (`Teh*` shows `teh*`), how it is written is behind the Inputs heading's info mark (D-L88), and a `*` anywhere else, alone or doubled, is refused in plain words. The `*` may be called the wildcard. A file's older `match` that Ark cannot read is refused in the same words, without naming the four. The panel publishes each input both ways: its stored letters, which name it in an edit, and as it is written.

Four named matches were a choice a person had to understand before typing a word, repeated on every row, for something most entries never use. Written into the input, the default needs nothing and the rest is one character where the eye already is. Whether an entry fires as you type, after the Leader key or both is the entry's, not an input's, so its inputs stay one list (D-L91).

## A replacement is text or a macro

A replacement is one line of text of up to 128 bytes, or a macro slot the keyboard plays (firmware D-F68, D-F69). An entry that plays a macro has no text and its `macro`; among the entries it is named by a key no text can be (`entryKey`), which is what the panel publishes as an entry's `id`, what Review's unit and a finding's place name, and what the screen marks. The screen shows a macro by its name and offers Text or Macro wherever a replacement is typed or changed. A macro plays for a whole word only, so an input with `*` is refused for one; it may fire after the Leader key as text does (D-L91). A replacement whose macro has no steps is a warning in its editor and a check in Review (`inertAutocorrectMacro`), the way a pointing mode that runs an empty macro is said: the keyboard accepts it and does nothing, so the profile carries it.

## Refusals and warnings

The list's rules have one home in core, `core/model/autocorrect-list.js`, working on the model the codec reads and writes (`core/schema/autocorrect-domain-v1.js`), so the draft only ever holds a list the keyboard takes. Two kinds of finding come from it:

- **A refusal** stops an edit, in words: what the firmware's validator would refuse (an empty or over-long text, a character an input may not hold, an input that is its replacement, one another replacement has, a macro slot the keyboard lacks, a list past its ceilings), a `*` where it cannot go, and an entry the chosen host layout cannot type when it is added or edited, since the keyboard could not type its replacement.
- **A warning** is found on the list and never stops a save (finding them is bounded for a full list: the matcher's index is made once per list, and a draft revision's warnings are kept): a replacement or input the host layout no longer types after the layout changed, a replacement another entry would change again, two that replace each other, an input with `*` under four letters, one that also matches inside a replacement, and a macro with no steps. The keyboard skips an entry it cannot type, so a layout change must not make the profile unsaveable; since the layout is changed on another screen, Review says it too, as one warning for the whole list (`untypableAutocorrect`, `core/model/profile-checks.js`).

The list has two counted ceilings, replacements and inputs, both 1,024 on current firmware. Since a replacement always has an input, the first can never be met before the second, so the screen and the Keyboard screen's Memory panel show inputs against their ceiling and never a ceiling of replacements; core still holds both, and a list past either is refused by the one it passed.

The words an input may hold and what each folds to are the firmware's table, generated into `core/data/autocorrect-words.json` from the pinned fixture; Ark folds what is typed with it and never derives its own.

What is typed is checked before it is kept by making the edit of the draft as it stands and throwing the result away (`validateAutocorrect`, answered by `autocorrectValidation`), so the check and the edit cannot disagree, and the interface holds no rule of the list. It posts a field's text as it was typed and core reads its inputs from it, split at spaces (`splitInputs`, the rule a spreadsheet's inputs cell is read by). The check also answers with the entry the edit's replacement is in the list, its name, and whether the list already has it (`editNames`), so the screen never decides when two replacements are the same: it offers to open the one the list has, and follows an entry whose replacement changed, by what core said. The screen posts an edit only once its check has passed, so what core refuses stays in its field with the reason under it, never in a toast after the field was emptied; inputs entered one straight after another wait their turn, each checked against the list as the one before it left it. The search is a plain one over what is published, a replacement's label and its inputs as written.

The list's size is counted once (`autocorrectCounts`, beside the codec), for every ceiling an edit, a backup, an import and the Memory panel judge it by.

Review's unit is the entry (`UNIT.autocorrect`), named by its key as the keyboard has it and, when the draft changed its replacement, by both keys. An entry only the keyboard has is paired with the entry only the draft has that took most of its inputs, and shown as one item, changed. Discard puts an entry back with its inputs, each taken from wherever the draft moved it.

## Input, not typed

Ark first called an input "typed" ("12 typed", "what is typed for it"). A participle made a poor noun: it had no plural, a count read as a verb, and a sentence needed five words for it. It is an **input**: "15 of 1,024 inputs", "+ Input", "“teh” is already an input for “the”". Ark's own list files say `inputs` (D-L85), and the ones that said `typed` are still read. The code and the wire keep `typo`, as they keep `correction`.

## Considered options

A row per input, as QMK's text format lists them: the same replacement would be written and stored once per input, and adding another way of typing it would mean writing it again. A menu or four buttons for where an input matches: tried first, and it read as a decision to make on every entry. A regular-expression-like syntax: more than the keyboard stores, and nothing a person should need to learn for "also fix recieved". Long text as a second kind of replacement stored in the list: the profile already has macros, with their own memory, editor and names; a replacement that names one needs no second store. Naming a macro replacement by the macro's name in the list: a macro is renamed and reordered on its own screen, and the keyboard stores a slot. Letting the draft hold an entry the keyboard refuses and blocking the save in Review: every other edit keeps the draft a profile the keyboard takes, and a refusal where it is typed says what to fix sooner. Refusing a list a layout change left untypable: the layout is changed on another screen, for other reasons, and the keyboard already skips what it cannot type. Naming an entry by its place in the list: the stored order is by the text's bytes, so a place moves under every edit.
