# A keyboard that stopped saving says so, and Ark restarts it

Cited as D-L67.

A keyboard whose profile storage stopped refuses every Save, Revert and edit until it restarts, which otherwise looks like a keyboard that is not ready or a slave half catching up. Ark shows it as one state, stopped, which outranks every other state the keyboard reports, with Restart as the only action (firmware D-F34). It does so in every edit mode: under an Apply draft the look between edits reads the same flags, so a refused Apply never reads as a keyboard that is not ready. Restart first keeps any unsaved edits as a recovery copy, asks both halves to restart, follows the same keyboard back as after a rename (D-L62), reads it once it has finished starting (D-L70), and puts the edits back unsaved as one live edit (`core/session/keyboard-restart.js`). An Apply draft holds no edits on the keyboard, so it needs no recovery copy and stays as it is across the restart, edits and draft history included, while the keyboard holds what the draft began from; Ark looks at the keyboard again at once, so one that stopped again says so, and an Apply it would refuse is refused as stopped. A keyboard whose slave half never confirmed a cancelled save (peer cleanup pending, `health.restartNeeded`) refuses new saves until it restarts too, so the bar offers the same Restart for it, in every edit mode; a keyboard that says both gets one bar, the stopped one (`restartOffer`, `webview/view/edit-mode.mjs`). Ark offers Restart only when the keyboard says it stopped or needs a restart and never restarts it by itself, since a restart loses what runs unsaved and only a person should choose that over unplugging. Firmware without restart never sets the stopped flag, so no capability check is needed; asked to restart, it answers unhandled and Ark says to unplug the keyboard.

## Considered options

Keeping a restart the keyboard needs to the keyboard dot's hover words and the Keyboard screen, with unplugging as the way out: dropped, Noah's call, 2026-10-27. The keyboard refuses saves until it restarts, which a hover hides, and Ark's Restart keeps the unsaved edits that unplugging loses.

Offering Restart in the keyboard menu at any time: dropped, because a restart otherwise is a choice about losing unsaved edits that only the stopped state, or a restart the keyboard needs, makes for the person, and a half left apart after an unacknowledged restart rejoins by itself (firmware D-F34).
