# A person reads a failure in Ark's words

Cited as D-L75.

What a person reads of a failure is a sentence Ark wrote for them, never a code, a developer word or the text of a decoder, the language or the browser (`failureSentence`, `core/model/vocabulary.js`). Ark's own failure, a plain `Error` or one carrying Ark's code (`SERVICE_BUSY`, `TIMEOUT`), says its message as written (`sayable`). A fault in Ark or beneath it, a language error such as a `TypeError`, the browser's own error or a byte format's refusal marked `fault: "ark"`, says `FAILURE_WORDS.unexpected`, unless it says a person's edit would not fit (`CAPACITY_EXCEEDED`), which the draft refuses in `PROFILE_FULL_WORDS` before the keyboard sees it, by the count it went past as the usage table names it, or as the profile being full. A format's refusal of a person's choice, such as a name too long, says itself. An answer from the keyboard that does not read is marked `fault: "answer"`, by the protocol that reads it or, where Ark reads the profile's bytes with a format it also uses for its own, by `answerFault` and `answered` (`core/schema/bytes.js`); it says `FAILURE_WORDS.unreadable`, or `FAILURE_WORDS.incompatible` when the firmware answers in a form this Ark does not read. The text of a fault or an answer goes only to the device service's diagnostics. A sentence Ark wraps around a failure carries over only Ark's code (`arkCode`), so a fault beneath it does not make the whole sentence read as a fault's. A decoder's text names bytes and offsets and a `TypeError`'s names Ark's code; neither tells a person what happened or what to do, and the three sentences each do: try again, read the keyboard again, update the firmware. The contract is [An Apply or Save cut short](../spec/interface-contracts.md#an-apply-or-save-cut-short).

## Considered options

Showing a failure's own message: rejected, because a person then reads a byte offset or "Cannot read properties of undefined". Telling a fault from an answer by the error's class: rejected, because a byte format Ark reads for both its own bytes and the keyboard's throws the same error for both, and only where it was read says whose it is. Words for every code: rejected, because a fault has no code Ark chose, and a person can do no more with a sentence per code than with the three.
